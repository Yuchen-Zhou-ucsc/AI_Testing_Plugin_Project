| 项目     | 内容                                        |

| 文档版本   | v1.0                                      |
| 项目负责人  | Yuchen Zhou                               |
| 更新时间   | 2026-08-13                                |
| 对应 PRD | `docs/PRD.md`                             |

## 2. 文档目的

本文档将 PRD 中的产品需求转化为可以开发、检查和测试的明确系统需求，并规定各接口的输入、处理规则、返回状态和数据结构。

本文档只描述系统应有的行为以及当前代码中的对应位置，不填写测试输入、实际响应、通过率或测试结论。真实测试数据将在 `Test_Cases.xlsx` 和 `Test_Report.md` 中记录。

## 3. 系统组成

系统由以下四个部分组成：

| 系统部分       | 主要功能                      | 对应位置                     |
| ---------- | ------------------------- | ------------------------ |
| React 前端   | 注册、登录、欢迎页面、AI 测试页面和测试结果展示 | `frontend/src/`          |
| Flask 后端   | 提供注册、登录、AI 用例生成和自动测试接口    | `backend/app.py`         |
| SQLite 数据库 | 保存用户账号、密码哈希和创建时间          | `backend/users.db`       |
| OpenAI 服务  | 根据自然语言需求生成结构化测试用例         | `/api/ai/generate-tests` |

## 4. 需求优先级说明

| 优先级 | 说明                  |
| --- | ------------------- |
| P0  | MVP 必须具备，否则核心流程无法运行 |
| P1  | 对流程完整性、安全性或可靠性有重要影响 |
| P2  | 可以在后续版本继续扩展         |

## 5. 功能需求规格

### 5.1 用户注册需求

| 需求编号    | 优先级 | 前置条件或输入             | 系统处理要求            | 预期输出                  | 代码对应情况                   |
| ------- | --- | ------------------- | ----------------- | --------------------- | ------------------------ |
| REG-001 | P0  | 用户名为空或去除首尾空格后为空     | 系统拒绝注册            | HTTP 400；提示用户名和密码为必填项 | 已在前端和后端实现                |
| REG-002 | P0  | 用户名长度少于6个字符         | 系统应拒绝注册           | HTTP 400；不得写入数据库      | 产品需求已定义；代码故意未实现，用作预埋 Bug |
| REG-003 | P0  | 密码为空字符串             | 系统拒绝注册            | HTTP 400；提示用户名和密码为必填项 | 已在前端和后端实现                |
| REG-004 | P0  | 用户名已经存在于数据库         | 系统拒绝重复注册          | HTTP 409；提示用户名已存在     | 已通过数据库唯一约束和异常处理实现        |
| REG-005 | P0  | 用户名和密码符合要求，且用户名未被使用 | 系统创建用户记录          | HTTP 201；返回注册成功信息     | 已在注册接口实现                 |
| REG-006 | P1  | 注册请求通过输入校验          | 系统先生成密码哈希，再保存用户记录 | 数据库只保存密码哈希，不保存明文密码    | 已通过 Werkzeug 密码哈希功能实现    |

补充规则：

* 后端在处理用户名前使用 `strip()` 去除首尾空格。
* 用户名在数据库中必须唯一。
* 当前系统未规定密码最小长度或复杂度，只要求密码不是空字符串。
* `REG-002` 是本项目唯一需要保留的业务规则类预埋 Bug。

### 5.2 用户登录需求

| 需求编号      | 优先级 | 前置条件或输入    | 系统处理要求               | 预期输出                     | 代码对应情况    |
| --------- | --- | ---------- | -------------------- | ------------------------ | --------- |
| LOGIN-001 | P0  | 用户名或密码为空   | 系统拒绝登录               | HTTP 400；提示用户名和密码为必填项    | 已在前端和后端实现 |
| LOGIN-002 | P0  | 用户名存在且密码正确 | 系统验证密码哈希并返回用户信息      | HTTP 200；前端保存当前用户并进入欢迎页面 | 已实现       |
| LOGIN-003 | P0  | 用户名存在但密码错误 | 系统拒绝登录               | HTTP 401；返回统一错误信息        | 已实现       |
| LOGIN-004 | P0  | 用户名不存在     | 系统拒绝登录               | HTTP 401；返回与错误密码相同的错误信息  | 已实现       |
| LOGIN-005 | P1  | 系统验证登录密码   | 系统使用密码哈希验证，不直接比较明文密码 | 验证结果正确且不返回密码或密码哈希        | 已实现       |

补充规则：

* 错误密码和不存在的用户名统一返回 `Invalid username or password`，避免通过错误信息判断某个用户名是否存在。
* 登录成功响应只包含用户 ID 和用户名，不包含密码哈希。
* 前端只有在登录接口成功返回后才保存当前用户信息并进入欢迎页面。

### 5.3 AI 测试用例生成需求

| 需求编号   | 优先级 | 前置条件或输入             | 系统处理要求                | 预期输出                                                 | 代码对应情况                    |
| ------ | --- | ------------------- | --------------------- | ---------------------------------------------------- | ------------------------- |
| AI-001 | P0  | 用户在 AI 测试页面输入自然语言需求 | 前端将去除首尾空格后的需求发送至后端    | 后端接收到 `requirement` 字段                               | 已实现                       |
| AI-002 | P0  | 需求为空                | 前端禁止提交；后端同时执行非空校验     | HTTP 400；提示需求为必填项                                    | 已实现                       |
| AI-003 | P0  | 用户提交有效需求            | AI 按照 Prompt 生成5条测试用例 | 测试编号依次为 TC-001 至 TC-005                              | 已通过 Prompt 规定；当前没有额外的数量校验 |
| AI-004 | P0  | AI 分析产品需求           | 生成场景应覆盖正常、边界和异常情况     | 返回不同类型的测试场景                                          | 已通过 Prompt 规定             |
| AI-005 | P0  | AI 返回测试用例           | 后端使用 Pydantic 验证结构    | 每条用例包含规定的全部字段                                        | 已实现                       |
| AI-006 | P0  | 测试用例用于自动执行          | 请求方法、地址和请求体必须可以被执行器读取 | `request_method`、`request_url` 和 `request_body` 结构有效 | 已实现                       |
| AI-007 | P1  | 测试用例生成成功            | 前端读取返回的测试用例数组         | 页面使用表格展示生成结果                                         | 已实现                       |

每条测试用例必须包含以下字段：

| 字段                     | 数据类型  | 说明          |
| ---------------------- | ----- | ----------- |
| `test_case_id`         | 字符串   | 测试用例编号      |
| `test_scenario`        | 字符串   | 测试场景        |
| `preconditions`        | 字符串   | 测试前置条件      |
| `test_steps`           | 字符串列表 | 测试步骤        |
| `test_data`            | 字符串   | 便于人工查看的测试数据 |
| `expected_result`      | 字符串   | 预期结果说明      |
| `request_method`       | 字符串   | HTTP 请求方法   |
| `request_url`          | 字符串   | 被测试接口地址     |
| `request_body`         | 对象    | 实际发送给接口的请求体 |
| `expected_status_code` | 整数    | 预期 HTTP 状态码 |

`request_body` 必须包含：

| 字段         | 数据类型 | 说明         |
| ---------- | ---- | ---------- |
| `username` | 字符串  | 注册测试使用的用户名 |
| `password` | 字符串  | 注册测试使用的密码  |

### 5.4 自动化测试执行需求

| 需求编号     | 优先级 | 前置条件或输入                           | 系统处理要求                      | 预期输出                                          | 代码对应情况 |
| -------- | --- | --------------------------------- | --------------------------- | --------------------------------------------- | ------ |
| TEST-001 | P0  | 提交符合结构要求的测试用例                     | 后端逐条读取并执行测试用例               | 返回每条测试用例的执行结果                                 | 已实现    |
| TEST-002 | P0  | 测试用例包含请求方法和接口地址                   | 执行器只允许 `POST /api/register` | 不支持的接口被标记为 Error，不执行请求                        | 已实现    |
| TEST-003 | P0  | 测试用例预期状态码为409，且用户名测试前不存在          | 系统先创建前置账号，再执行重复注册请求         | 实际执行满足重复用户名的前置条件                              | 已实现    |
| TEST-004 | P0  | 注册接口返回响应                          | 系统记录实际状态码和实际响应内容            | 结果包含 `actual_status_code` 和 `actual_response` | 已实现    |
| TEST-005 | P0  | 已获得预期和实际状态码                       | 系统比较两个状态码                   | 一致时标记 Pass，不一致时标记 Fail                        | 已实现    |
| TEST-006 | P1  | 自动测试执行完成                          | 前端读取执行结果                    | 页面显示预期状态码、实际状态码和测试状态                          | 已实现    |
| TEST-007 | P1  | 测试返回 HTTP 201，用户名非空，并且该用户名在测试前不存在 | 系统在执行后删除该测试账号               | 减少成功注册测试产生的数据库残留                              | 已实现    |

执行结果必须包含以下附加字段：

| 字段                   | 数据类型   | 说明                      |
| -------------------- | ------ | ----------------------- |
| `actual_status_code` | 整数或空值  | 接口实际返回的 HTTP 状态码        |
| `actual_response`    | 对象或空值  | 接口实际返回的 JSON 内容         |
| `test_status`        | 字符串    | `Pass`、`Fail` 或 `Error` |
| `error_message`      | 字符串或空值 | 无法执行测试时的错误说明            |

测试汇总必须包含：

| 字段       | 数据类型 | 说明      |
| -------- | ---- | ------- |
| `total`  | 整数   | 执行结果总数  |
| `passed` | 整数   | Pass 数量 |
| `failed` | 整数   | Fail 数量 |

## 6. API 接口规格

### 6.1 健康检查接口

| 项目    | 规格                      |
| ----- | ----------------------- |
| 请求方法  | `GET`                   |
| 接口地址  | `/api/health`           |
| 请求体   | 无                       |
| 成功状态码 | HTTP 200                |
| 成功响应  | 包含 `status` 和 `message` |
| 用途    | 检查 Flask 后端是否正在运行       |

### 6.2 用户注册接口

| 项目         | 规格                                            |
| ---------- | --------------------------------------------- |
| 请求方法       | `POST`                                        |
| 接口地址       | `/api/register`                               |
| 请求体字段      | `username`、`password`                         |
| 请求体不是 JSON | HTTP 400；`Request body must be JSON`          |
| 用户名或密码为空   | HTTP 400；`Username and password are required` |
| 用户名少于6个字符  | 按需求应返回 HTTP 400；当前代码故意未实现                     |
| 用户名重复      | HTTP 409；`Username already exists`            |
| 注册成功       | HTTP 201；`Registration successful`            |

### 6.3 用户登录接口

| 项目         | 规格                                            |
| ---------- | --------------------------------------------- |
| 请求方法       | `POST`                                        |
| 接口地址       | `/api/login`                                  |
| 请求体字段      | `username`、`password`                         |
| 请求体不是 JSON | HTTP 400；`Request body must be JSON`          |
| 用户名或密码为空   | HTTP 400；`Username and password are required` |
| 用户不存在或密码错误 | HTTP 401；`Invalid username or password`       |
| 登录成功       | HTTP 200；返回用户 ID 和用户名                         |

### 6.4 AI 测试用例生成接口

| 项目          | 规格                                              |
| ----------- | ----------------------------------------------- |
| 请求方法        | `POST`                                          |
| 接口地址        | `/api/ai/generate-tests`                        |
| 请求体字段       | `requirement`                                   |
| 请求体不是 JSON  | HTTP 400；`Request body must be JSON`            |
| 需求为空        | HTTP 400；`Requirement is required`              |
| AI 调用失败     | HTTP 500；`Failed to generate test cases`        |
| AI 未返回结构化结果 | HTTP 500；`AI returned no structured test cases` |
| 生成成功        | HTTP 200；返回原始需求和结构化测试用例                         |

### 6.5 自动化测试执行接口

| 项目         | 规格                                          |
| ---------- | ------------------------------------------- |
| 请求方法       | `POST`                                      |
| 接口地址       | `/api/tests/execute`                        |
| 请求体字段      | `test_cases`                                |
| 请求体不是 JSON | HTTP 400；`Request body must be JSON`        |
| 测试用例结构无效   | HTTP 400；`Invalid test case data`           |
| 测试执行完成     | HTTP 200；返回 `summary` 和 `execution_results` |
| 用例请求范围     | 只允许执行 `POST /api/register`                  |
| 不支持的用例     | 对应测试结果标记为 `Error`                           |

## 7. 数据库规格

数据库文件位于 `backend/users.db`，正式 Git 仓库不保存该数据库文件。

`users` 表结构如下：

| 字段              | 数据类型      | 约束     | 说明     |
| --------------- | --------- | ------ | ------ |
| `id`            | INTEGER   | 主键、自增  | 用户唯一编号 |
| `username`      | TEXT      | 非空、唯一  | 用户名    |
| `password_hash` | TEXT      | 非空     | 密码哈希   |
| `created_at`    | TIMESTAMP | 默认当前时间 | 账号创建时间 |

数据库规则：

1. `username` 必须唯一。
2. 数据库中不得保存明文密码。
3. 旧数据库如果使用 `password` 字段，初始化程序将其重命名为 `password_hash`，并将旧数据转换为密码哈希。
4. `users.db` 应由 `.gitignore` 排除，不得上传到 GitHub。

## 8. 安全和范围限制

1. OpenAI API Key 只能保存在 `backend/.env` 中。
2. `.env`、`.venv` 和 `users.db` 不得上传到 GitHub。
3. 自动测试执行器只允许调用 `POST /api/register`。
4. 登录失败时不得向前端返回密码哈希。
5. 当前登录状态使用浏览器 `localStorage` 保存，只适用于本地 MVP 演示。
6. 当前系统不是生产环境账号系统，不包含令牌认证、角色权限、密码找回和多因素认证。
7. 当前版本不连接真实企业 Bug 管理平台。

## 10. 测试数据记录原则

1. 本文档不填写实际测试数据。
2. 测试用户名、密码、执行时间和实际响应必须来自后续真实测试。
3. AI 生成内容可能在不同调用之间变化，因此最终测试用例应保存一次实际生成的完整结果。
4. 实际状态码和 Pass/Fail 必须来自程序执行，不得人工编造。
5. 测试完成后，再根据真实结果编写测试报告和 Bug 报告。
